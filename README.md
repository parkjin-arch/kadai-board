# 課題ボード

授業・課題・個人タスクをまとめて管理する、スマホ優先の Web アプリ（PWA）。
ビルド不要の HTML + CSS + JavaScript（ES Modules）なので、フォルダをそのまま GitHub Pages に置けば動く。

## ファイル構成

```
index.html              画面の骨組み（タスク / 時間割 / 設定 / 編集ダイアログ）
manifest.webmanifest    PWA 設定（ホーム画面に追加したときの名前・アイコン）
sw.js                   Service Worker（オフラインで開けるようにキャッシュ）
css/style.css           スタイル（スマホ優先・ダークモード対応）
data/timetable.json     時限の定義と、初回起動時に読み込む時間割（初期データ）
icons/                  アプリアイコン
js/
  app.js                画面の描画とイベント処理
  config.js             設定（段階2の同期を有効にするときだけ編集）
  store.js              保存層（localStorage）。タスク・シフト・ノートで共通のコレクション
  parser.js             1行入力の解析
  shifts.js             バイトのシフト（繰り返しの展開・例外・集計・重なり検出・.ics）
  notes.js              今週のノート（箇条書き・チェックの解釈）
  calendar.js           Googleカレンダー追加 URL と .ics 生成
  timetable.js          時限の定義と授業の検索（休講・補講・教室変更、次回の授業の計算など）
  events.js             自分で追加する予定（複数日・終日）
  agenda.js             授業・バイト・予定・タスク期限をカレンダー用の「項目」にまとめる
  calendar-view.js      カレンダーの描画（月・週・日・年）
  holidays.js           日本の祝日の計算
  dom.js                DOM の小さなヘルパー
  dateutil.js           日付ユーティリティ
  gcal-sync.js          段階2：Calendar API 自動同期（設定したときだけ読み込まれる）
  firebase-store.js     段階2：Firestore 保存層（設定したときだけ読み込まれる）
```

**設計方針**

- 保存層は `store.js` の `LocalCollection`（`add / update / put / remove / all / get / subscribe / getMeta / setMeta`）で抽象化している。タスク・シフト・ノート・授業・予定はそれぞれ別のコレクション。`firebase-store.js` は同じ形で実装してあるので、`config.js` の `storage` を切り替えるだけで移行できる。
- タスクは `{ id, title, due(ISO), courseId, priority, memo, estimateMin, done, gcalEventId, createdAt, updatedAt }`。授業は `timetable.json` の `id` で参照している。
- 段階2のコードは動的 `import()` で読み込むので、使わないあいだは読み込まれず、余計な処理も走らない。

## 使い方メモ

### 1行入力

| 書き方 | 意味 |
|---|---|
| `回路理論B` `回路` `DSA` `シス解` | 授業（`timetable.json` の name / aliases） |
| `11/6` `11月6日` `2026/11/6` | 日付（時刻を書かなければ 23:59） |
| `今日` `明日` `明後日` `3日後` | 相対日付 |
| `金曜` `来週月曜` | 曜日 |
| `次回` | その授業の次のコマの開始時刻 |
| `23:59` `9時半` `2限` | 時刻 |
| `!高` `!低` `!!` `至急` | 優先度 |
| `2h` `1.5時間` `90分` | 所要時間 |

例：`アルゴリズム 小テスト 次回` → 「小テスト」／データ構造とアルゴリズム／次の月曜 17:00

入力中は、解析結果が入力欄の下にプレビューされる。`…` ボタンを押すと、解析結果を入れた状態で詳細入力ダイアログが開く。

### Googleカレンダー

- 各タスクの 📅 → Googleカレンダーの予定作成画面が開く（期限を終了時刻とし、所要時間ぶんさかのぼった時刻を開始にする。所要時間が未設定なら 30 分）
- 設定 → `.ics をエクスポート` → Googleカレンダーの「設定 → インポートとエクスポート」で読み込む。UID が固定なので、同じタスクを再インポートしても重複しない

### カレンダー（日・週・月・年）

- 上部の「日・週・月・年」で切り替え、「今日」で今日に戻る。「＋」から予定・タスク・バイトを追加
- 授業・バイト・タスク・予定のボタンで、表示する種類を絞り込める
- **月表示**：日〜土の7列。上下にスクロールすると前後の月が続けて読み込まれる。複数日の予定（旅行 11/6〜11/10 など）は1本のバーで描き、週の折り返しでは端を角張らせて続いて見えるようにしている。日付をタップするとその日の一覧が開き、そこから予定・タスク・バイトを追加できる
- **祝日**：`js/holidays.js` で「国民の祝日に関する法律」のルールから計算（振替休日・国民の休日・2019〜2021年の特例を含む）。2019〜2027年について、内閣府の祝日CSVをもとにした holidays-jp API と一致することを確認済み。オフラインでも動き、将来の年も表示できる。法改正があったら、このファイルのルールを直す
- **週表示・日表示**：縦軸が時刻。終日の予定は上の「終日」欄に横長のバーで出る。曜日の見出しをタップすると日表示へ
- **年表示**：12か月のミニカレンダー。予定・バイト・タスク期限・休講や補講のある日に点が付く（毎週の授業には付けない）。月をタップすると月表示へ
- ダークモードでは背景が黒になり、今日の日付は赤い丸で示す

### 週表示（授業・バイト・期限）

- 月〜日の7列 × 時間軸。授業（時間割の色）・バイト（緑の斜線）・タスクの期限（▲の札）を同じ週に並べる
- 時刻は分単位で位置と高さを決めるので、19:00–21:30 のように時限に合わない予定も正しく描ける。時間の重なる予定は横に並べる
- 日をまたぐシフト（22:00–02:00 など）は、翌日の分を列の上端に表示
- 授業とバイト、バイト同士が重なったとき、タスクの期限がバイト中・授業中のときは ⚠ で警告（週の上部・タスク一覧・保存時のお知らせ）。期限が授業の開始時刻ちょうど（「次回提出」など）は重なりとみなさない

### バイトのシフト

- 「＋ バイト」から **単発** と **毎週** を登録（毎週は開始日・終了日つき。終了日なしなら無期限）
- 週間ビューでシフトをタップ → **この日だけ休み / この日だけ時間変更 / 元に戻す**（毎週シフトの例外）
- 各シフトに「Googleカレンダーに追加」（この日だけ / 毎週の予定として）。.ics エクスポートにも含まれる（毎週は RRULE、休みは EXDATE、時間変更は RECURRENCE-ID で出力）
- 時給を入れると、表示中の週と月の勤務時間・概算収入を集計。同じ勤務先は前回の時給を自動で入れる

### 今週のノート

- タスク・週間画面の一番下。週ごとに保存され、‹ › で過去や先の週に切り替えられる
- 入力が止まって 0.5 秒後に自動保存（アプリを閉じたときも保存）
- `- ` で始まる行はチェックできる項目になる（チェック済みは `- [x] ` として保存）
- 新しい週を開くと、先週の未チェック項目を引き継ぐか選べる（1回選ぶと、その週はもう聞かない）

### 時間割（授業の追加・編集・削除）

- 初回起動時に `data/timetable.json` の授業を読み込み、以後はアプリ上で自由に編集する（授業は別のデータとして保存される）
- 空きコマをタップすると、その曜日・時限が入った状態で追加画面が開く。「＋ OD授業を追加」でオンデマンド授業を追加できる
- 授業をタップすると「タスク一覧・編集・休講/補講/教室変更・削除」を選べる
- 1つの授業に複数のコマを持たせられる（回路理論B：木2・金5 など）。連続コマは「月 3〜4限」のように1行で入力する。タスクは授業1つに紐づく
- 同じコマに別の授業を入れようとすると警告が出る（もう一度押せば重なったまま保存できる）。時間割では ⚠ と点線の枠で表示する
- 削除するときは、紐づいたタスクを「一緒に削除」するか「授業なしとして残す」かを選ぶ（直後なら「元に戻す」もできる）
- **休講・補講・教室変更**：その日だけの変更を登録すると、カレンダー・重なりの警告・「次回」の計算に反映される

### 学期の切り替え

設定 →「学期を切り替える」で、**授業だけ**をリセットする（タスク・バイト・予定・ノートは消えない）。

- 新しい時間割は「空から始める」か「`data/timetable.json` を読み込む」を選べる
- 「今の授業をアーカイブとして残す」を選ぶと、過去のタスクに授業名が残る（アーカイブはバックアップにも含まれる）

## ローカルで動かす

ES Modules と `fetch` を使っているので、`index.html` をダブルクリックで開いても動かない。ローカルサーバーを立てて開く。

```sh
cd task
python -m http.server 8000
# → http://localhost:8000
```

## デプロイ（GitHub Pages）

1. GitHub で新しいリポジトリ（例：`kadai-board`）を作る
2. このフォルダをプッシュする
   ```sh
   git init
   git add .
   git commit -m "first commit"
   git branch -M main
   git remote add origin https://github.com/<ユーザー名>/kadai-board.git
   git push -u origin main
   ```
3. リポジトリの **Settings → Pages → Build and deployment** で Source を「Deploy from a branch」、Branch を `main` / `/ (root)` にして Save
4. 1〜2分後に `https://<ユーザー名>.github.io/kadai-board/` で公開される（パスはすべて相対パスなので、サブパスでもそのまま動く）

**Vercel を使う場合**：vercel.com で GitHub リポジトリを Import → Framework Preset は「Other」、Build Command は空のまま Deploy。

### iPhone のホーム画面に追加

Safari で公開 URL を開く → 共有ボタン → 「ホーム画面に追加」。

> ⚠ localStorage は「Safari」と「ホーム画面のアプリ」で**別々に保存される**。使うのはホーム画面のアプリに統一するのがおすすめ。また PC と iPhone のデータは段階1では共有されない（段階2の Firebase で共有できるようになる）。

### 更新したとき

`sw.js` の `CACHE = 'kadai-board-v1'` の番号を上げてからデプロイする。キャッシュはバックグラウンドで更新されるので、反映は**次回アプリを開いたとき**になる。

## Googleカレンダー自動同期

タスクの期限・バイトのシフト・自分の予定を、専用カレンダー「課題」に自動で書き込む（授業は量が多いので送らない）。実装は `js/gcal-sync.js`。

- 毎週のシフトは繰り返しの予定になる。「この日は休み」は繰り返しから外し（EXDATE）、「この日だけ時間変更」は別の予定として作る
- 完了したタスクは「✓」付きのグレーの予定になる。アプリで削除したものはカレンダーからも消える
- **送信待ち方式**：変更したデータには `gcalDirty: true` が付き、削除したものは設定の `gcalDeletes` に積まれる。接続中ならすぐ送る
- ブラウザだけで動くアプリなので、Google の接続は約1時間で切れる。切れたあとに変更すると、画面上部に「📅 同期待ち N件」が出るので、押すと送られる（Firebase を使っていれば、送信待ちは端末をまたいで残る）。アプリを閉じている間に自動で送るにはサーバー（有料の Cloud Functions など）が必要

### 設定手順（Firebase と同じ Google Cloud プロジェクトを使う）

1. https://console.cloud.google.com/ で、Firebase のプロジェクトを選ぶ
2. **API とサービス → ライブラリ** で「Google Calendar API」を検索 → 有効にする
3. **API とサービス → OAuth 同意画面**（「Google Auth Platform」の場合は「データアクセス」「対象」）
   - スコープに `https://www.googleapis.com/auth/calendar.app.created` を追加（このアプリが作ったカレンダーだけを操作できる、いちばん狭い権限）
   - 公開ステータスが「テスト」なら、**テストユーザー**に自分の Gmail アドレスを追加
4. **API とサービス → 認証情報** の「Web client (auto created by Google Service)」（Firebase が作ったもの）を開く
   - 承認済みの JavaScript 生成元に `https://parkjin-arch.github.io` と `http://localhost:8000` を追加して保存
   - **クライアント ID** を `js/config.js` の `google.clientId` に入れる
5. アプリの設定 →「Googleカレンダーに接続」→ 許可。今あるデータがまとめて送られる

## クラウド保存：Firebase（Firestore + Googleログイン）で端末間同期

実装は `js/firebase-store.js` にある。`LocalTaskStore` と同じインターフェースなので、UI 側の変更は不要。

### 設定手順

1. https://console.firebase.google.com/ → **プロジェクトを追加**（上で作った Google Cloud プロジェクトを選ぶと、まとめて管理できる）
2. **Authentication → 始める → Sign-in method → Google** を有効化
3. **Authentication → 設定 → 承認済みドメイン** に `<ユーザー名>.github.io` を追加
4. **Firestore Database → データベースを作成**（ロケーションは `asia-northeast1`（東京）、本番環境モード）
5. **ルール** タブに次を貼り付けて公開する（自分のデータは自分しか読み書きできない）
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /users/{uid}/{document=**} {
         allow read, write: if request.auth != null && request.auth.uid == uid;
       }
     }
   }
   ```
6. **プロジェクトの設定 → マイアプリ → ウェブアプリを追加（</>）** → 表示された `firebaseConfig` の値を `js/config.js` の `firebase` にコピーする（値が入っていれば自動でクラウド保存になる）
7. デプロイ → 画面上部の「Googleでログイン」。初回ログイン時に、この端末のデータ（タスク・シフト・ノート・授業・予定・学期の設定）をアカウントへ移すか1回だけ聞かれる

**しくみと注意**

- データは `users/{uid}/tasks/{id}`・`shifts/{id}`・`notes/{週の月曜}`・`courses/{id}`・`events/{id}` に保存される。`onSnapshot` で購読しているので、PC で追加したタスクがすぐにスマホにも表示される。
- オフラインキャッシュ（`persistentLocalCache`）を有効にしているので、電波のないところでも追加・編集でき、オンラインに戻ると同期される。
- カレンダーの ID は `users/{uid}/meta/settings` に保存されるので、PC とスマホで同じ「課題」カレンダーに書き込まれる。
- **iPhone のホーム画面アプリでのログイン**：ポップアップが使えない場合はリダイレクト方式に切り替える。ただし Safari はサードパーティの保存領域を制限しているため、GitHub Pages（`github.io`）と `firebaseapp.com` のようにドメインが分かれていると、リダイレクトでのログインがうまくいかないことがある。そのときは **Firebase Hosting でホストする**（`firebase init hosting` → `firebase deploy`）のが確実で、`authDomain` と同じドメインになるので問題が起きない。
- Firebase の apiKey も公開して問題ない値（アクセスはセキュリティルールで制御する）。

### 両方を有効にした場合

PC とスマホのどちらで編集しても、編集した端末から Calendar API が呼ばれる。イベント ID はタスクと一緒に Firestore に保存されるので、イベントが重複して作られることはない。
